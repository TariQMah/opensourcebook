# Glossary

The words on screen and the names in code. Screen words follow `VISION.md` and `DECISIONS.md` #30 and #33 to #39. Code and database names stay as they are; this file is the one place the mapping is recorded. When a word changes on screen, change it here first.

## Words on screen

| On screen | In code / database | Meaning |
|---|---|---|
| project | `projects` table · `Project` (Swift) | A container for sources and plans: a course, a paper, a topic, anything. |
| source | `sources`, `source_extractions`, `source_chunks` · `SourceKind` (Swift) | A file, link, note or recording brought into Open Sourcebook. Extracted once, cached by hash. |
| topic | `category` (`projects.category`, `outputs.category`, `Project.category`) | An automatic grouping above projects and things that stand on their own. Was "category". |
| Inbox | `ShareInbox` (Swift, share extension) | Sources not yet filed into a project. |
| chat | `sessions`, `messages` | A saved conversation in a project, grounded in the selected sources. Was "session". |
| Studio | none (the right panel of a project) | The panel on the right of a project: a tile for each thing Open Sourcebook makes and one for a plan, and below them one list of everything made or being made. It makes things with no chat, and plays them. Was the web mode for planning. Only "Studio type" became "format". |
| made at once | `plans.direct` (one item, started at once) · `make_item`, `remake_item` · `POST /v1/projects/:id/make` | One thing made with no card to approve, from its make sheet's button, a make tile, or the `opensourcebook` command in a terminal. Asked for in the chat (a `/<format>` command, "make me a quiz on chapter 3"), it first opens its make sheet filled in (a `make` reply piece) and nothing is made until the person presses the sheet's button. Shown as the thing itself. A remake points back through `supersedes_plan_id`. Not a screen word: the person sees the thing. |
| plan | `plans` · `Plan` (Swift) · `planning` skill | Ordered items for a project: stages, side-by-side items, branches. No calendar unless the person gives stages days. Its command is Plan a whole subject (`/plan`). Was also "album". |
| item | `plan_nodes` row; once made, an `outputs` row (`outputs.node_id`) · `Output` (Swift) | One thing in a plan: a format, a brief, its sources, the format's settings, a cost. Was "node". "Output" is not a screen word. |
| stage | `plan_nodes.level` | A step in plan order. Items on one level are side by side and may not assume each other. |
| stage label | `plan_stages.label` | Optional free text naming a stage. |
| day (of a stage), due | `plan_stage_dates.due_on` · `GET /v1/due` · `POST /v1/plans/:id/catch-up` | The day the person means to go through a stage by, only when they gave one. "Due" is a dated stage with something left that was missed, falls today or this week; "Move the days on" moves missed days to today, keeping the gaps. |
| branch | `plan_nodes.parent_id` + `plan_nodes.condition_json` (`kind`: `metric`, `ask`, …; `ConditionRegistry`) | An item that runs only when a condition on an earlier item's result holds, including "ask me". |
| brief | `plan_nodes.prompt`, `outputs.prompt` | What the planner tells the engine about this item: purpose, coverage, what to assume and not repeat. Purposes like "diagnostic" or "mock exam" live here. |
| settings | `plan_nodes.settings_json`, `outputs.settings_json` | Whatever the item's format declares (length, pass mark, narration, …). |
| cost | `plan_nodes.est_cost_usd`, `outputs.cost_usd`, `usage` | Estimated or actual spend, in dollars. Kept in the data only: no screen shows money (see Activity). |
| Start | `plans.status`, `plans.kicked_off_at` | Begins generating a plan. Was "kick off". |
| done tick | `item_results.done_at` | Set when the person finishes or swipes past an item. Same on phone and web. |
| result | `item_results.result_json` | What the person's run through an item reported (a quiz's score, what was missed, an "ask me" answer). Read by branches and by later items as an input. |
| citation | `cites[].locator` (quiz payload; `SourceLocator`, character ranges today) · `source_chunks.locator_json` | Points at the exact spot it came from: a paragraph, an image, a graph, a table, a cell, a moment in a recording. Today locators are character ranges in a passage. |
| your agent | `agent_turns.agent`, `AgentChat` (`engine/src/chat/agent/`) · an adapter in `services/agent-connector/src/agents/` | The person's own coding agent (Claude Code, Codex, OpenCode, Antigravity, Cursor or GitHub Copilot), on their computer with their own login, answering the chat inside Open Sourcebook (`DECISIONS.md` #53). |
| provider | `GET /v1/providers` · `provider_settings` · `engine/src/chat/providers.ts` · Settings › Providers | One of your own agents that can answer the chat and make things (Claude Code, Codex, OpenCode, Antigravity, Cursor, GitHub Copilot), with whether it can now, whether it's on, how to install and sign in to it, and which models show (`DECISIONS.md` #62). Listed A to Z: no provider is preferred. With nothing picked, the only one ready is used; with several ready, Open Sourcebook asks which (`409 pick_needed`) and makes nothing until it is picked (#112). "Default" on a provider means only the chat's pick. |
| who answers | `answerer` on a chat · `AnswererPicker` (web) | The picker under the chat box: which of your providers answers this chat, and with which model. |
| What makes what | `GET /v1/providers` (`picks`) · `PUT /v1/providers/picks/:scope`, `PUT /v1/providers/picks` · `web/src/screens/settings/MakersSettings.tsx` | The Settings section, a table with a row for the chat and for each shape and the columns Made by, Reviewed by, Voice and Usually takes. It is the only place a default is set (`DECISIONS.md` #108): a make sheet or a plan item changes one thing and never a default. "Use one for all" sets the chat and every shape at once. In a terminal, `opensourcebook makers`. |
| make sheet | `web/src/make/MakeSheet.tsx` · `make` reply piece · `POST /v1/projects/:id/make` | The one sheet, opened in a project's right column, that makes any one shape: the sources it reads, the shape's settings, and the Made by box (Made by, Reviewed by, Voice). A make tile, a thing asked for in the chat and a plan item each open it filled in. Nothing is made until its button is pressed ("Make the video"), and what is picked on it is for that one thing. |
| Made here | `web/src/project/StudioPanel.tsx` | The list under Make in a project's right column: everything made or being made in the project, a row each, with Play or Open once made, a ⋯ menu that deletes it (asking first) and a Stop while it is made. Failed and stopped things can be cleared together. |
| Activity | `GET /v1/activity` · `web/src/screens/Activity.tsx` · Settings › Advanced › See what the agents are doing | The page of what the agents are doing: what is being made now, and every finished agent turn with what it was for, how long it took, its tokens read and written and its tool calls, with totals for today and the last 7 days. It shows no money. |
| first-time setup | `GET` and `PUT /v1/setup` · `web/src/firstrun/` · `/welcome` | Four steps on a fresh install: Get set up, Providers (connect the agents you use), Voice (which can be skipped, and the skip is remembered) and Try it. It resumes where the person left. Everything in it but Get set up is also in Settings. |
| Get set up | `web/src/setup/` · `cli/setup.ts` · `GET /launcher/setup` | One list of what this computer needs to make a video with a voice (a coding agent, signed in, ffmpeg, a voice), each with what is wrong in plain words and the one button that fixes it: install an agent from its adapter's npm package, start the agent's own sign-in in the browser and watch it finish, fetch ffmpeg, set up the free voice. Check again looks for everything anew. |
| voice service | `services/scenes/src/voices.ts` · `GET /v1/voice` · `.opensourcebook/voice.json` · Settings › Voice | Where a voice comes from: a hosted one that needs the person's key (ElevenLabs, Speechify), or one that runs on this computer (Kokoro, the computer's own). The app picks a service, takes its key once and shows only that one is set and its last four characters, then picks one of its voices, each with a sample. The choice is kept in a private file on this computer (`DECISIONS.md` #115). |
| connector | `services/agent-connector` · `CHAT_AGENT_URL` | The small program on the person's computer that runs their agent for Open Sourcebook's chat, with only Open Sourcebook's tools. |
| thread | `messages.content.about` · `/v1/plans/:id/items/:itemId/thread` · `describeAnchor` on a format · `web/src/thread/` | The talk on one made thing, opened and closed on it: what the person asked or disagreed with at a spot in it, and the answers. Each message is a message of the chat that made the thing (a new chat for a thing made from the Studio), so the answer shows in both. Shown as "Talk about this". |
| scene remake | `POST /v1/outputs/:id/scenes/:scene/remake` · `FormatDefinition.remakeScene` · `web/src/thread/remake.ts` | One scene of a made video made again, from its talk thread, with the person's note: **Remake this scene**. It is made as a new video with the unchanged speech kept, and once made it takes the old video's place (`DECISIONS.md` #116, #119). |
| teach-back | `teachBack` skill, `/teachback` (`engine/src/chat/teach-back.ts`) · `teachback` reply block (`engine/src/chat/blocks.ts`) · `TeachBackPieceView` (web) | The person explains an idea from their sources in their own words, in the chat, and Open Sourcebook answers with what they got right, what they left out and what the sources say differently, each point with its cite. Its command is Explain it back (`/teachback`); just explaining starts it too. Only in the chat: it makes nothing. |
| mind map | `mindMap` skill, `/mindmap` (`engine/src/chat/mind-map.ts`) · `mindmap` reply block (`engine/src/chat/blocks.ts`) · `MindMapPieceView` (web, laid out by `web/src/project/mindMap.ts`) | The main ideas of the sources, or of a topic in them, drawn round the central one with how they connect, in the chat. Tapping an idea shows its sentence, the cites that open its passages, and its links. Its command is Map the ideas (`/mindmap`); asking plainly starts it too. Only in the chat: it makes nothing. |
| step | `agent_steps` · `Message.steps` | One thing the agent did in a turn, in plain words ("Searching Lecture 7"), shown while it works. |
| folder (on Home) | `project_groups` table, `projects.group_id` · `/v1/groups` · `web/src/screens/HomeFolders.tsx` | A folder on Home the person keeps projects in, one folder a project or none. Deleting one puts its projects back on Home. Named a group in code so it is never mixed up with a linked folder (`projects.folder_path`), the folder on the computer whose files are a project's sources. |
| backup | `GET /v1/backup` · `POST /v1/backup/restores` · `engine/src/backup/` · Settings › Backups | One zip of every project with everything in it and the files of what was made, and a `manifest.json` saying what is in it. Restoring adds what is not here and asks, for a project that is, whether to keep both, replace it or skip it. Only on the person's own computer. |
| "No project" (Library filter only) | `outputs` row with `project_id` NULL | Something made outside any project. Since `DECISIONS.md` #46 everything lives in a project, so nothing new should be made this way; older ones show in the Library under "No project". |

## What Open Sourcebook makes

Five shapes (`DECISIONS.md` #33 to #37, the row that made the byte flashcards, and the rows that added audio and the guide): **video to watch, flashcards to swipe, quiz to check, audio to listen to, and a guide to keep**. Their ids are `video`, `flashcards`, `quiz`, `audio` and `guide`; older ids (`byte`, `bits`, `read`, `cards`, `check`) are aliases that resolve to them, so stored rows keep working.

| On screen | In code / database | Meaning |
|---|---|---|
| (why a format can't be made here) | `problem` on a format view (`GET /v1/formats`) · `unavailable` on `FormatDefinition` | One sentence on what stops a format on this computer now and what to do (audio with no voice key). Shown on its tile, said by its command and read by the planner. |
| format | `FormatId`, `FormatDescriptor`, `FormatRegistry` (`engine/src/studio/`) · `GET /v1/formats` · `plan_nodes.type`, `outputs.type` · `FormatID`, `FormatDescriptor`, `FormatCatalog`, `FormatRegistry` (Swift, `ios/OpenSourcebook/Models/`) · engine interface `OutputEngine` | One of the five shapes an item is made as. Was "Studio type". |
| (a format's few words) | `blurb` on `FormatDescriptor` (`GET /v1/formats`) | What a format is in a few plain words, for a person meeting the word ("cards to swipe and flip, brought back until they stick"). Shown beside the label where the format is first offered or planned; the longer `about` is for the planner. |
| video | `video` · `engine/src/engines/video/` | A short explainer you watch, drawn scene by scene. Nothing sideways. |
| flashcards (a set of flashcards) | `flashcards` (aliases `byte`, `bits`, `read`, `cards`) · contract `CardSet` in `engine/src/cards/contract.ts`, `engine/docs/flashcards.md` · makers in `engine/src/engines/flashcards/` · `FlashcardsPlayer` (web) | Cards to swipe and flip, each doing one job, brought back over days until they stick. The person marks each card got it or not yet (or answers it); a missed card comes back in the same sitting. Was "byte" (bits read one screen at a time) until Nov 18, 2026; stored bytes open as cards. |
| card | `Card` (`engine/src/cards/contract.ts`): `front`, `back`, `cites` | One screen of a set: a front, and usually a back it turns over to. Never exists alone. Was "bit". |
| kind of card | `CardKindRegistry` (`engine/src/cards/kinds.ts`): `recall`, `cloze`, `compare`, `steps`, `formula`, `worked`, `picture`, `ask`, `explain` | The one job a card does: front and back, fill the gap, compare, steps, a formula, a worked example, a picture to name, a question that checks itself, or a point explained. Open: a new kind is one entry. On screen by its label ("Front and back", "Fill the gap", ...). Was "kind of bit". |
| got it / not yet | `progress.cards[id]` on the plan item (`box`, `due`, `seen`, `missed`) · `web/src/player/spacing.ts` | How the person marks a card after turning it over. |
| due | a card whose `due` time has passed (`isDue`) | A card that comes back for review now. "Review N due" is one tap in a set and due sets come first in the feed. |
| learned | a card in box 3 or higher (`LEARNED_BOX`) | Got on three reviews spread over days, in a row. |
| audio (an audio walk-through) | `audio` · contract `AudioPayload` in `engine/src/engines/audio/contract.ts`, `engine/docs/audio.md` · maker in `engine/src/engines/audio/` · voiced by `services/scenes/src/audio.ts` · `AudioPlayer` (web) | A spoken walk-through with no picture, for walking, commuting or doing something else: one voice, the transcript with each word's time, each part's cites. Not ready (with why) when the computer has no voice. |
| part (of an audio) | `parts[]` (`AudioPart`): `title`, `text`, `background`, `cites`, `words` | One stretch of what the voice says, tied to the passages it draws on, or background: the maker's own explanation, said aloud as such. |
| background | `background` (a card's block, a chat reply's block, an audio's part, a guide's point) | What a maker or the chat adds beyond the person's sources: never cited, shown (or, in audio, said) as not from them. |
| guide | `guide` · contract `GuidePayload` in `engine/src/engines/guide/contract.ts`, `engine/docs/guide.md` · maker in `engine/src/engines/guide/` · `GuidePlayer` (web) | A page or a few of notes to keep, print and change by hand: sections of points, every claim with its cite. A reference, not a lesson. Its length is printed pages. |
| point (of a guide) | `sections[].points[]` (`GuidePoint`): `term`, `text`, `background`, `cites`, `yours`, `made` | One claim, definition, step or formula on a guide, with an optional term shown first. "Yours" when the person wrote or changed it; a changed point keeps the maker's words to put back. |
| change it (by hand) | `PUT /v1/outputs/:id/payload` · `edit` on `FormatDefinition` | Changing a made thing's words yourself, for a format that takes it (a guide). The format lays the change over what it keeps; nothing typed adds a cite. |
| quiz | `quiz` · `engine/src/engines/quiz/` (old id `check`, an alias) | Questions with feedback, any length; its own engine and look. An exam is a long quiz: a practice exam is one with a **time limit** (`timeLimit`, minutes from Start) and a **format to follow** (`layout`, the real paper in the person's words), usually with feedback at the end. Was "check". |
| kind of quiz question | `QuestionKindRegistry` (`engine/src/engines/quiz/kinds.ts`, listed in `default-kinds.ts`): `choice`, `worked`, `order`, `match`, `complete`, `graph`, `label` | What one question is: a choice, a problem worked in steps with hints, things to put in order, pairs to match, working to fill in, a line to draw on a graph, or a picture's marks to name. Open: one file in `kind/` and one piece in `web/src/player/quiz/`. On screen by its label ("Put in order", "Match pairs", ...). |
| maker | `VideoMaker` (`engine/src/engines/video/makers.ts`), `ItemMaker` (`engine/src/engines/makers.ts`) | What makes the content of a set of flashcards, a quiz or a video: a meme, a clip from your own source, a worked example, a story. Open. Built: the video maker **Drawn scenes** (`scenes`, written by your own agent; local only; DECISIONS #54), and for flashcards and quizzes **your agent** (`agent`) and **the model API key** (`api`; #66). An item's `maker` setting picks one; "Open Sourcebook decides" by default. Only real makers make anything: there are no stand-ins (#69). On screen it is also the person's pick of who does the making, shown as **Made by**: an agent, a model and an effort, set per shape in What makes what and per thing on a make sheet or a plan item (`DECISIONS.md` #108). |
| reviewer | the agent field with `role: review` on a format (`GET /v1/formats`) · `<shape>.review` pick | Shown as **Reviewed by**: who looks over what was made and gives the maker one more round. Only a shape that declares a review turn offers one (today video). On by default with the maker's own pick; the person may give it its own agent, model and effort, or turn it off (`DECISIONS.md` #109). |
| no time yet | `GET /v1/make-times` · `web/src/make/makeTime.ts` | What a pick says when nothing was made with that same agent, model and effort (and length group, where the shape has them) on this computer. A time is only ever said from such runs, "Usually takes about 4 min"; it is never a guess or another pick's time (`DECISIONS.md` #111). |
| no sound | `render.audio: false`, `voice.note` | A video made without a voice key: the file has no audio track and its captions carry the words. Said plainly at start, before it is made, on the video and in every `opensourcebook` answer, in one line from the scenes service (DECISIONS). Not an error. |
| style | `VideoMakerStyle` | How a maker's video looks (Chalkboard, Blueprint, ...), picked by picture. Each maker brings its own. |
| storyboard | `render.storyboard: true` | A video made before Nov 18, 2026 by the storyboard maker, now gone (#69): white frames with each scene's plan written on them, no sound. It still plays. Nothing makes one now. |

Removed as formats (`DECISIONS.md` #33 to #35): **read** and **bits** (served as flashcards now), **check** (now quiz), **guided work** (a kind of quiz question), **slides**. The **byte** became **flashcards** on Nov 18, 2026: the plain reading screens went, what was worth keeping (a card that flips, a comparison, steps, a formula, a worked example, a question) became kinds of card. Audio became the fourth shape on Nov 18, 2026 (it is in the feed, one screen like the others, and starts on a tap); talking out loud is still not planned (#38). The guide became the fifth on Nov 20, 2026: notes to keep, print and change by hand.

Format ids are open strings declared in the engine's registry and served with their label, colour slot, icon and settings by `GET /v1/formats`. Badges and player messages show a format's label exactly as the descriptor writes it, lower case, on phone and web. A stored id no registry knows is kept and shown with a neutral badge. The iPhone ships a copy of the `GET /v1/formats` answer and replaces it with the engine's at launch.
